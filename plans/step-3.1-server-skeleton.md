# Шаг 3.1. Каркас сервера на Node.js 22 LTS

## Цель
Простой сервер, который показывает форму из `public/`, отвечает на проверочный адрес `/api/health` и готовит папку для данных. Заявки, база, кабинет и уведомления на этом шаге не делаются.

## Ограничения (из PROJECT.md)
- Никаких npm-зависимостей: только встроенные модули Node (`node:http`, `node:fs`, `node:path`, `node:url`). В `package.json` не должно быть разделов `dependencies` и `devDependencies`.
- Не менять `public/`, `furniture/`, `PROJECT.md`, `TASK.md`.
- Не вписывать секреты ни в какие файлы. В `.env.example` у секретов только пустые значения.
- Делать только этот шаг.

## package.json
- `"name": "pwa-master-apps"`, `"private": true`, `"type": "commonjs"`.
- `"engines": { "node": ">=22.13" }` (с этой версии встроенный SQLite работает без флага, он нужен на шаге 3.2).
- `"scripts": { "start": "node server/index.js" }`.

## server/index.js
1. **Настройки из `.env`.** Если в корне проекта есть файл `.env`, загрузить его через `process.loadEnvFile(путь)`. Если файла нет, работать без него и не падать. Сами значения в журнал не выводить.
2. **Параметры:**
   - `PORT`, по умолчанию `3000`;
   - `DATA_DIR`, по умолчанию папка `data` в корне проекта. Относительный путь считать от корня проекта, а не от текущей папки терминала.
3. **Папка данных.** При запуске создать `DATA_DIR` и `DATA_DIR/photos` (`fs.mkdirSync(..., { recursive: true })`). Если создать не удалось, вывести понятную ошибку и завершиться с кодом 1.
4. **Маршруты:**
   - `GET /api/health` возвращает `200` и JSON `{"ok":true}`.
   - Все остальные `GET` и `HEAD` раздают файлы из `public/`, при этом `/` открывает `index.html`.
   - Другие методы получают `405`, неизвестные адреса `404` с коротким текстом.
5. **Безопасность раздачи файлов:**
   - адрес декодировать через `decodeURIComponent` внутри `try`, а при ошибке отвечать `400`;
   - отбросить `?query`, собрать путь через `path.resolve` и проверить, что он остаётся внутри папки `public/`. Иначе ответ `404`;
   - не отдавать файлы и папки, имя которых начинается с точки;
   - для папок (кроме корня) отвечать `404`.
6. **Типы файлов.** Небольшая таблица: `.html`, `.css`, `.js`, `.json`, `.png`, `.jpg`/`.jpeg`, `.webp`, `.svg`, `.ico`, `.webmanifest`, `.txt`. Для текстовых типов добавить `charset=utf-8`. Для остальных расширений `application/octet-stream`.
7. **Заголовки во всех ответах:** `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`. Для файлов ещё `Cache-Control: no-cache`.
8. **Ошибки.** Непредвиденная ошибка даёт `500` с текстом «Внутренняя ошибка сервера». Технические подробности пишутся только в консоль, клиент их не видит.
9. **Журнал запуска.** Одна строка: `Сервер запущен: http://localhost:<PORT>, данные: <DATA_DIR>`.
10. Код сделать простым и разбить на небольшие функции с короткими комментариями на русском. Позже в этот же файл добавятся маршруты `/api/requests` и `/admin`.

## Раздел в README
Коротко и простыми словами:
1. Установить Node.js 22 LTS с nodejs.org.
2. Скопировать `.env.example` в `.env` (файл `.env` никому не передавать и никуда не выкладывать).
3. В терминале в папке проекта выполнить `npm start`.
4. Открыть `http://localhost:3000`, должна появиться форма. По адресу `http://localhost:3000/api/health` должно быть написано `{"ok":true}`.
5. Заявки и фото будут храниться в папке `data/`, на сервере в `/data`.

## Готово, когда
- `npm start` запускает сервер без установки пакетов.
- Форма открывается на `http://localhost:3000`, `config.json` подгружается, цвета и услуги видны.
- `/api/health` отдаёт `{"ok":true}`.
- Адреса вида `/../package.json`, `/%2e%2e/.env`, `/.env` не отдают файлы.
- После запуска появляются папки `data/` и `data/photos/`.
- `public/` и `furniture/` не изменены.
