# Техническое задание №1: Загрузка и раздача логотипа компании (Бэкенд)

Этот документ описывает архитектуру и шаги реализации бэкенд-части для управления логотипом компании. Все изменения производятся в рамках существующих файлов сервера без добавления новых зависимостей и без изменения схемы базы данных.

## Архитектура и требования

### 1. Хранилище логотипа
- Папка для логотипа: `DATA_DIR/branding` (где `DATA_DIR` берется из конфигурации сервера).
- Папка должна создаваться автоматически при старте сервера в функции `prepareDataDirs()` в файле `server/index.js`.
- В папке должен находиться ровно один файл логотипа. При загрузке нового файла старый должен удаляться.

### 2. Публичный маршрут: `GET /api/logo`
- Возвращает файл логотипа из папки `DATA_DIR/branding/`.
- Заголовки ответа:
  - `Content-Type`: Соответствует расширению файла (image/png, image/jpeg, image/webp).
  - `Cache-Control`: `no-cache`
- Если логотип не загружен (папка пуста или файла нет) — возвращает статус `404 Not Found` с текстовым или JSON-ответом.
- Реализуется в `server/index.js` в функции `handleRequest`.

### 3. Защищённый маршрут: `POST /api/admin/logo`
- Доступен только авторизованному менеджеру: проверка через `auth.checkSession(req)`. Если сессия неактивна — возвращает `401 Unauthorized` `{ ok: false, error: 'Необходима авторизация' }`.
- Принимает `multipart/form-data`.
- Разбор тела запроса выполняется с помощью функции `parseMultipart` из `server/multipart.js`.
- **Лимиты и проверки**:
  - Максимальный размер файла: 2 МБ (2 * 1024 * 1024 байт).
  - Проверка сигнатуры файла (Magic Bytes):
    - JPEG: первые байты `FF D8 FF`
    - PNG: первые байты `89 50 4E 47 0D 0A 1A 0A`
    - WebP: первые байты `RIFF` (смещение 0) и `WEBP` (смещение 8)
    - SVG и другие форматы запрещены.
  - Если проверки не пройдены — возвращает `400 Bad Request` с описанием ошибки.
- **Сохранение**:
  - Перед сохранением нового файла удаляет любые старые файлы из папки `DATA_DIR/branding/`.
  - Сохраняет файл в `DATA_DIR/branding/logo.<ext>` (где `<ext>` соответствует оригинальному расширению или определенному типу).
  - Возвращает `{ ok: true }` со статусом `200 OK`.

### 4. Защищённый маршрут: `POST /api/admin/logo/delete`
- Доступен только авторизованному менеджеру (проверка сессии).
- Удаляет текущий файл логотипа из `DATA_DIR/branding/`.
- Возвращает `{ ok: true }` со статусом `200 OK`.

## План реализации для Кодера (режим Code)

### Шаг 1. Подготовка окружения и папок
В [`server/index.js`](server/index.js):
1. Импортировать `parseMultipart` из `./multipart`.
2. Определить константу `BRANDING_DIR` как `path.join(DATA_DIR, 'branding')`.
3. Обновить функцию `prepareDataDirs()` для создания папки `BRANDING_DIR` рекурсивно (`fs.mkdirSync(BRANDING_DIR, { recursive: true })`).

### Шаг 2. Добавление защищённых маршрутов управления логотипом
В [`server/index.js`](server/index.js) в секции `// ---------- Защищённые API кабинета менеджера ----------` добавить:
1. `POST /api/admin/logo`:
   - Проверить сессию менеджера.
   - Прочитать сырое тело запроса аналогично тому, как это делается в `requests.js`, используя буфер и лимит размера тела.
   - Выполнить `parseMultipart` для извлечения файлов. Найти поле с логотипом.
   - Проверить размер и сигнатуру.
   - Очистить папку `BRANDING_DIR` от старых файлов.
   - Записать новый файл с правильным именем и расширением.
   - Вернуть JSON-ответ.
2. `POST /api/admin/logo/delete`:
   - Проверить сессию менеджера.
   - Очистить папку `BRANDING_DIR`.
   - Вернуть JSON `{ ok: true }`.

### Шаг 3. Добавление публичного маршрута раздачи логотипа
В [`server/index.js`](server/index.js) в секции перед отдачей статики:
1. `GET /api/logo`:
   - Проверить, есть ли файлы в `BRANDING_DIR`.
   - Если файлы отсутствуют, вернуть `404 Not Found`.
   - Если файл есть, отдать его с правильным `Content-Type` (на основе расширения) и заголовком `Cache-Control: no-cache`.

### Шаг 4. Верификация
1. Убедиться, что тесты запускаются и успешно проходят:
   ```bash
   npm run check:db
   npm run check:requests
   ```
2. Изменения не затрагивают схему БД SQLite, поэтому тесты базы данных не сломаются.
