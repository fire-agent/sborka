# PWA для мастеров: ремонт мебели и ремонт окон

## Что планируется

Две отдельные PWA на общей основе:

- приложение для ремонта мебели;
- приложение для ремонта окон.

Общая основа: один набор экранов и логики заявки, отдельная установка под каждого мастера.

## Как клиент отправляет заявку

- Клиент открывает форму по ссылке.
- Регистрация клиента не требуется.
- Для заявки нужно приложить от 1 до 5 сжатых фотографий.

## Оплата

- Цену работы и оплату клиент согласует с мастером напрямую, вне приложения. Внутри приложения оплаты нет.
- Мастер разово платит **4 900 ₽** за приложение для выбранной ниши.
- Первоначальная настройка входит в эту сумму.
- Размещение в **Amvera** мастер оплачивает отдельно.

## Безопасность и запуск

- **HTTPS обязателен** до приёма реальных заявок.

## Нерешённые вопросы

Статус по этим пунктам пока не определён, решения не приняты:

- обработка и срок хранения контактных данных, заявок и фотографий, а также порядок их удаления;
- хранение заявок и фотографий в Amvera;
- авторизация мастера — пока не выбрана;
- резервное копирование;
- порядок создания и передачи аккаунта Amvera.

## Примечание по Amvera

В документации Amvera указано, что постоянное хранилище приложения обычно доступно по пути `/data`; туда рекомендуют сохранять SQLite и другие данные, которые должны сохраняться при перезапуске и пересборке. [«Хранилище и пути»](https://docs.amvera.ru/applications/storage.html) и [«SQLite»](https://docs.amvera.ru/databases/sqlite.html).

В FAQ Amvera также сообщает о нескольких экземплярах данных и регулярных резервных копиях. Это не отменяет необходимости проверить процедуру восстановления для приложения; см. нерешённые вопросы выше. [«Не сохраняются данные при перезапуске/пересборке приложения/базы данных»](https://docs.amvera.ru/general/FAQ/data-saving.html).

Примечание описывает сведения из документации платформы, а не текущую настройку нашего приложения.

## База данных и её проверка

- Заявки хранятся в файле `data/app.db` (на сервере `/data/app.db`). Файл создаётся сам при запуске `npm start`.
- Это файл с данными клиентов: его нельзя выкладывать в интернет и в репозиторий (папка `data/` уже исключена).
- Чтобы проверить, что база работает, выполнить в терминале `npm run check:db`. Должна появиться строка «Все проверки базы пройдены».
- Если в консоли появляется жёлтое предупреждение про `SQLite is an experimental feature`, это нормально: оно не мешает работе.
- Чтобы начать с чистой базы на компьютере, остановить сервер и удалить файлы `app.db`, `app.db-wal`, `app.db-shm` в папке `data/`.

## Приём заявок и его проверка

- Сервер принимает заявки по адресу `/api/requests`. Принимается телефон, описание, услуга из списка и от 0 до 5 фото (JPEG, PNG или WebP, не больше 4 МБ каждое). Форма на сайте пока ещё не отправляет заявки, это будет следующим шагом.
- Фото сохраняются в папку `data/photos/` под случайными именами, данные заявки в `data/app.db`.
- Защита от спама: скрытое поле для роботов, не больше 10 заявок за 10 минут с одного адреса, ограничение размера.
- Параметр `TRUST_PROXY` в `.env`: на компьютере оставить `false`, на сервере Amvera поставить `true` (иначе все посетители будут считаться одним человеком). Если после выкладки лимит срабатывает у всех сразу или не срабатывает вовсе, нужно проверить это значение.
- Проверка: в терминале выполнить `npm run check:requests`. Должна появиться строка «Все проверки приёма заявок пройдены». Настоящая папка `data/` при этом не затрагивается.
- Папка `furniture/` (старый образец Этапа 1) удалена. Настройки ниши «мебель» лежат в `public/configs/furniture.json`.

## Как сменить нишу и проверить на компьютере

### Как сменить нишу

1. Откройте папку `public/configs/`. В ней лежат готовые настройки: `furniture.json` (мебель) и `windows.json` (окна).
2. Скопируйте нужный файл, например `public/configs/windows.json`, и вставьте его на место `public/config.json` (с заменой).
3. Откройте `public/config.json` и поправьте название, заголовок, телефон, ссылки на мессенджеры, услуги и цены. Ссылки пишите полностью, начиная с `https://`. Пустая строка значит, что мессенджер не показывается. Цвета пишите в формате `#2b6cb0`.

Код страницы при этом менять не нужно.

### Как проверить на компьютере

1. Откройте папку `public` в VS Code через расширение «Live Server» и нажмите кнопку «Go Live».
2. Запасной вариант: откройте терминал в папке `public`, выполните `python -m http.server 8000` и откройте в браузере адрес `http://localhost:8000`.

**Важно:** двойной щелчок по `index.html` не подходит. Браузер не даст прочитать файл настроек, и страница покажет сообщение об ошибке.

## Как запустить сервер на компьютере

1. Установите Node.js 22 LTS с сайта nodejs.org.
2. Скопируйте файл `.env.example` и назовите копию `.env`. Файл `.env` никому не передавайте и никуда не выкладывайте.
3. В терминале в папке проекта выполните `npm start`. Ничего устанавливать дополнительно не нужно.
4. Откройте в браузере `http://localhost:3000`, должна появиться форма. По адресу `http://localhost:3000/api/health` должно быть написано `{"ok":true}`.
5. Заявки и фото будут храниться в папке `data/`, а на сервере — в `/data`.

## Кабинет менеджера

- Вход в кабинет: `http://localhost:3000/admin/login`. Пароль задаётся в `.env` через `ADMIN_PASSWORD`.
- Если `ADMIN_PASSWORD` не задан, вход в кабинет заблокирован. Это защищает от случайного открытия кабинета без пароля.
- После входа по адресу `http://localhost:3000/admin` менеджер видит список заявок и может:
  - фильтровать их по статусу («Новые», «В работе», «Выполнены», «Отклонены»);
  - искать заявки по имени или телефону;
  - изменять статус заявки;
  - просматривать приложенные фотографии в защищённом режиме;
  - удалять заявку (вместе с её фотографиями из `data/photos/`).
- Фотографии и данные кабинета доступны только после входа; посторонний по прямой ссылке получит перенаправление на страницу входа.

## Уведомления менеджера

При создании новой заявки сервер отправляет уведомление во все включённые мессенджеры:

- **Telegram** — через Bot API
- **MAX** — через platform-api.max.ru
- **WhatsApp** — через шлюз Green-API

### Настройка

Откройте файл `.env` (создайте его на основе `.env.example`, если ещё нет) и заполните параметры:

```
# Telegram (Bot API)
TELEGRAM_BOT_TOKEN=ваш_токен_от_BotFather
TELEGRAM_CHAT_ID=id_чата_или_канала

# MAX (MAX Bot API)
MAX_BOT_TOKEN=ваш_токен
MAX_CHAT_ID=id_чата_или_канала

# WhatsApp через шлюз Green-API
GREEN_API_URL=https://api.green-api.com
GREEN_API_ID_INSTANCE=id_инстанса
GREEN_API_TOKEN=токен_инстанса
WHATSAPP_CHAT_ID=номер_в_формате 79990000000
```

Включите нужные каналы в [`public/config.json`](public/config.json:35), установив `enabled: true` для выбранного мессенджера.

Уведомления отправляются асинхронно — ошибка или отключение одного мессенджера не влияет на сохранение заявки и ответ клиенту.

## Быстрый старт (10 минут)

### Вариант 1: Docker (рекомендуется)

1. Скопируйте `.env.example` в `.env` и заполните токены (TELEGRAM_BOT_TOKEN, MAX_BOT_TOKEN, GREEN_API_...)
2. Откройте [`public/config.json`](public/config.json) и замените:
   - `companyName` — название вашей компании
   - `title` и `subtitle` — заголовки страницы
   - `contacts.phone` — ваш телефон
   - `services` — список услуг и цен
3. Запустите:
   ```bash
   docker-compose up -d
   ```
4. Сайт доступен по `http://localhost:3000`

### Вариант 2: Обычный запуск

1. Установите Node.js 22 LTS
2. Скопируйте `.env.example` в `.env` и заполните токены
3. Откройте [`public/config.json`](public/config.json) и настройте параметры (как выше)
4. Выполните в терминале:
   ```bash
   npm install
   npm start
   ```
5. Сайт доступен по `http://localhost:3000`

### Вариант 3: Amvera

1. Загрузите проект в репозиторий
2. В `env` добавьте токены как переменные окружения
3. Установите `DATA_DIR=/data` и `TRUST_PROXY=true`
4. Добавьте том `/data` для хранения базы и фото
